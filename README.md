# 我的工作台（Worklife）

一个**只在这台电脑上跑、数据不上云、零运行时依赖**的个人工作生活工作台。九个模块：今日计划、自媒体、开发工作、咨询工作、健身、饮食、游戏娱乐、数据与设置，外加一个把它们串起来的首页。

纯原生 JS + 手写 CSS，不用构建工具、不装任何 npm 包，双击 `启动.bat` 就能用。

---

## 一、解决什么问题

日常真正要盯的事散落在四五个地方：任务在备忘录、项目 DDL 在日历、自媒体数据在后台截图、健身记录在本子、咨询问答在聊天记录、玩了多久游戏靠猜。切换成本高，久了就都不记了；而现成的效率 App 大多要登录、要会员、要联网同步，私人内容还得先想一遍"这能不能上传"。

这个项目针对的是三个具体问题：

1. **碎片化**：九类记录放进同一个界面，首页每天早上扫一眼就知道今天该动哪一块，不用逐个数。
2. **记不住**：把"填写"压缩到一两个动作（回车加任务、一行一个动作、点一下就打卡），降低记的门槛。
3. **数据归属**：不联网、无账号、无遥测，数据只存在本机浏览器数据库里，再配一份磁盘镜像和手动导出，清缓存也能救回来。

**明确不做**：不做手机端、不做多端同步、不做推送通知、不做多人协作。它是给自己用的单机工具。

## 二、主要功能

### 九个模块

| 模块 | 解决什么 | 核心操作 |
|---|---|---|
| **首页** | 一眼看清今天 | 问候语 + 今日进度环 + 六张摘要卡（开发、咨询、自媒体、健身、饮食、游戏），只有变色的才需要点进去 |
| **今日计划** | 今天做什么 | 上午 / 下午 / 晚上 / 未安排四个时段；回车加任务、勾选完成、拖动换时段、顺延到明天；昨日未完成可一键结转或丢掉；支持重复任务；一天结束可写「日终回顾」 |
| **自媒体** | 内容从选题到发布 | 看板五列（选题池 → 写作中 → 待发布 → 已发布 → 归档）拖卡改状态；「本周排期」看哪天发什么；「数据」视图看发布后的播放 / 点赞 / 涨粉 |
| **开发工作** | 有 DDL 的项目 | 一项目一卡，自动算剩余天数（逾期变红）；项目抽屉里记待办（可指定"下一步"）、开发日志、踩坑（问题 / 原因 / 解法），踩坑支持全局搜索 |
| **咨询工作** | 谁问了什么、我怎么答的 | 记录提问人与渠道，回复后写结论与后续；结论可一键存进「答案库」，下次同样问题直接复制；可按人查看历史、删除某个客户 |
| **健身计划** | 练了什么、练了多少 | 先给 7 天各定一套模板（或标休息）；点「开始训练」按模板生成组次，重量与次数沿用上次；月历格子直接显示当天部位、动作、组数 |
| **饮食计划** | 吃了多少热量 | 先在食物库维护常吃项（单位 / 热量 / 蛋白质），每餐「+ 吃了」选食物填份数，热量与蛋白质自动累计；四餐（早 / 午 / 晚 / 加餐）+ 饮水记录；月历显示每天热量，超标标红 |
| **游戏娱乐** | 别玩过头 | 设每周时长预算，开始 / 停止计时自动记时长，剩余时间首页可见；另有想玩清单 |
| **数据与设置** | 数据安全与个性化 | 深浅主题、周起始日、凌晨 4 点规则、四个目标值（热量 / 蛋白质 / 每周训练次数 / 每周游戏分钟）、导出备份、导入合并 / 覆盖、模块级或全量清空 |

### 跨模块能力

- **派生而非重复录入**：首页所有数字都由 `derive.js` 从九个模块的原始数据算出，不存第二份，改一处首页即时同步。
- **手动保存**：顶栏有保存按钮和实时保存状态，`Ctrl / ⌘ + S` 立刻落盘。
- **全局快速记录**：任意页面 `Ctrl / ⌘ + K` 随手记一条，进快速备忘，之后在首页「转任务」或「丢掉」。
- **月历视图**：健身与饮食都能按月翻看，点格子看当天明细（每个动作的每组次数与重量）。
- **凌晨 4 点规则**：0:00–4:00 记的内容算前一天，夜猫子友好，可在设置里关掉。
- **深浅双主题**、**零外部请求**（图标是内联 SVG，不引任何 CDN 或字体文件）。

## 三、安装方法

**不需要安装。** 项目没有构建步骤、没有 npm 依赖、不联网下载任何资源。

### 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 浏览器 | Chrome / Edge / Firefox 任一现代浏览器 | 必需 |
| Node.js | ≥ 18（可选，推荐） | 有 Node 时数据存 IndexedDB 并自动镜像到磁盘，最稳 |
| Python | 3.x（可选） | 没有 Node 但有 Python 时用它起静态服务 |

### 步骤

1. 把整个项目文件夹放到任意位置（例如 `C:\Users\你的用户名\Desktop\个人应用`）。
2. **Windows**：双击根目录的 `启动.bat`。
3. **macOS / Linux**：在项目根目录执行 `node server.js --open`。

`启动.bat` 会按顺序挑一条能走的路：

```
有 Node      → node server.js --open      默认 127.0.0.1:5173，自动开浏览器
有 Python    → python -m http.server 8000 --directory app
都没有       → 直接用浏览器打开 app/index.html
```

端口被占用时会自动往后试（最多换 10 次），以命令行窗口里打印的地址为准。想手动指定端口：cmd 里 `set PORT=6000 && node server.js`，PowerShell 里 `$env:PORT=6000; node server.js`。

> 用第三种方式（直接双击 `app/index.html`）也能正常用，但浏览器在 `file://` 下存储空间更小，页面顶部会出现一条黄色提示。**用完直接关掉那个黑色命令行窗口即可。**

### 可选：跑测试

测试只用于开发，运行时完全不需要。

```bash
cd tests
npm install        # 只装 jsdom，仅测试用
cd ..
node tests/run-all.js          # 全量
node tests/run-all.js media    # 只跑某个模块
```

删掉 `tests/` 目录不影响应用使用。

## 四、使用方法

### 日常动线

| 场景 | 怎么做 |
|---|---|
| 早上开工 | 打开首页扫一眼，哪张卡变色点哪张；点「今日计划」把今天三件事排进上午 / 下午 / 晚上 |
| 突然想到一件事 | `Ctrl / ⌘ + K` 记下来，不打断当前动作，之后再归类 |
| 项目临近 DDL | 「开发工作」建项目填截止日期，首页自动倒数；抽屉里记待办和踩坑 |
| 有人问技术问题 | 「咨询工作」记下谁问的、问什么，答完写结论并勾「存进答案库」 |
| 发完一条内容 | 「自媒体」把卡片拖到已发布，填发布数据，去「数据」视图看播放与互动率 |
| 健身当晚 | 点「开始训练」，组次按上次预填，只改变化的数字；练完在月历里回看 |
| 每餐之后 | 「饮食」点「+ 吃了」选食物填份数，热量自动累加 |
| 想玩游戏 | 「游戏娱乐」点开始计时，玩完点停止，本周剩余时间首页可见 |
| 每月一次 | 「数据与设置」→ 导出备份，把 JSON 存到网盘或 U 盘 |

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl / ⌘ + K` | 全局快速记录 |
| `Ctrl / ⌘ + S` | 立即保存（等同顶栏保存按钮） |
| `Esc` | 关闭当前抽屉 / 弹窗 |

### 数据存在哪

| 位置 | 作用 | 什么时候用 |
|---|---|---|
| 浏览器 IndexedDB（库名 `worklife`） | 主存储 | 用 `启动.bat` 打开时 |
| 浏览器 localStorage | 备用存储 | 直接双击 `index.html` 时 |
| `data/worklife.json` | 自动镜像 | 用 `启动.bat` 时每次改动自动落一份到磁盘 |
| 手动导出的 JSON | 正式备份 | 在「数据与设置」里点「导出备份」 |

数据**不联网、不上传**，只在这台电脑上。

### 备份与恢复

- **备份**：数据与设置 → 导出备份 → 得到 `worklife-backup-20261112-1130.json`。
- **导入并合并**：只补缺失的记录，现有数据不动（换电脑、补数据用这个）。
- **导入并覆盖**：先清空再写入，需要输入确认词「清空并恢复」（整机迁移用这个）。
- 超过 30 天没备份，首页页脚和设置页都会提醒。

### 常见问题

**页面空白 / 打不开** — 先看命令行窗口有没有报错；端口被占用会自动换，以窗口打印的地址为准。

**数据好像没了** — 先确认打开方式是否和上次一致（`启动.bat` 走 `127.0.0.1`，双击文件是另一套存储）。用 `启动.bat` 的话看 `data/worklife.json` 是否还在，或在设置里导入之前的备份。

**改坏了想重来** — 设置页危险区可以只清空某个模块，或全部清空，两者都需要输入确认词「清空」。

### 项目结构

```
app/
├─ index.html          唯一页面，按顺序引脚本（无构建）
├─ styles/             base（设计令牌与组件）/ layout（骨架）/ modules（模块特有）
└─ js/
   ├─ core/            util 日期与工具、db 存储适配、store 数据层、
   │                   derive 首页派生、ui 通用交互、router 路由
   ├─ logic/           九个模块的业务规则（纯逻辑，可单测）
   ├─ views/           九个页面的 render + mount
   └─ boot.js          启动顺序与保存状态
server.js              静态服务 + /api/data 数据镜像（97 行）
启动.bat               一键启动（Node → Python → 直接开文件）
tests/                 测试（仅开发用）
```

## 五、输入输出示例

以下输出均由当前代码实际运行得到。

### 1. 今日计划：加一条任务

**输入**（在「上午」栏输入框里敲，回车）

```
改完登录页接口文档
```

**输出**（写入 `tasks` 集合的一条记录，此处省略 `id` / `order`）

```json
{
  "title": "改完登录页接口文档",
  "date": "2026-11-12",
  "slot": "am",
  "moduleTag": "today",
  "estMin": null,
  "status": "todo",
  "repeatRule": "none"
}
```

### 2. 健身：周模板的动作输入格式

**输入**（一行一个动作，格式 `名称 组数x次数`，不写则默认 `3x10`）

```
卧推 4x8
侧平举 3x12
俯卧撑
```

**输出**（解析后的 `exercises`）

```json
[
  { "name": "卧推",   "targetSets": 4, "targetReps": 8  },
  { "name": "侧平举", "targetSets": 3, "targetReps": 12 },
  { "name": "俯卧撑", "targetSets": 3, "targetReps": 10 }
]
```

点「开始训练」后当天生成 3 个动作、共 10 组；第一组填 40kg 打完勾，当天概览变成：

```json
{ "part": "上肢 · 推", "exerciseCount": 3, "setCount": 10, "doneSets": 1, "volume": 320 }
```

`volume` = 8 次 × 40kg。

### 3. 自媒体：发布数据统计

**输入**：两条已发布内容填了数据

| 内容 | 平台 | 播放 | 点赞 | 涨粉 |
|---|---|---|---|---|
| 大一新生怎么选笔记本 | 小红书 | 12000 | 800 | 210 |
| 宿舍收纳改造 | B站 | 3400 | 150 | 45 |

**输出**（「数据」视图顶部的 KPI 与排序，互动率 = 点赞 ÷ 播放）

```json
{ "count": 2, "view": 15400, "like": 950, "fans": 255, "avgView": 7700, "engagement": 6.2 }
```

单条列表按播放量降序：`大一新生怎么选笔记本` 6.7% → `宿舍收纳改造` 4.4%。

### 4. 数据与设置：导出备份

**输入**：点击「导出备份」

**输出**：下载 `worklife-backup-20261112-1130.json`

```json
{
  "app": "worklife",
  "version": 1,
  "exportedAt": "2026-11-12T03:26:00.000Z",
  "settings": {
    "theme": "light",
    "weekStart": 1,
    "dayCutoffHour": 4,
    "goals": { "kcal": 1800, "protein": 120, "weeklyWorkouts": 3, "weeklyGameMin": 600 },
    "lastBackupAt": null
  },
  "data": { "tasks": [], "memos": [], "contents": [], "...": "共 18 个集合" }
}
```

### 5. 数据与设置：导入备份

**输入**：选择上面的 JSON，模式「导入并合并」

**输出**（返回新增与跳过的条数）

```json
{ "added": 0, "skipped": 5, "mode": "merge" }
```

同一份数据再导一次就是 `added: 0`——已存在的记录按主键跳过，不会重复。若选「覆盖」模式，需先输入确认词「清空并恢复」。

## 六、边界与已知限制

- **单机单用户**：没有账号体系，换机器要手动迁移数据（导出 → 导入覆盖）。
- **无手机端**：界面按桌面浏览器 1440px 宽设计，窄屏能看但不算好用。
- **无推送**：不会有系统通知提醒，靠每天打开首页。
- **清浏览器缓存有风险**：`启动.bat` 模式下有 `data/worklife.json` 兜底，但正式备份仍然要自己做。
- 素材与数据文件都在本地，不含任何第三方账号授权或网络请求。
